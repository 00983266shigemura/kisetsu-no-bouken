# 開発・成果保全・リリースゲート v1.1

適用対象：きせつのぼうけん。現行mainと既存PRの成果を保護する。本文は運用ガイドであり、実機検証や公開完了の証拠ではない。

## Gate 0 — 回収と正本
- main、全関連ブランチ、PR、コミットSHAを確認し、既存画像・教材・QA証跡の所在を照合する。
- Work専用環境にある可能性のある未保存成果は「未回収」とする。未生成と断定せず、削除・上書き・重複生成しない。
- Work利用不能時も、独立した教材調査・設計・テスト・既存コード確認は継続する。
- 回収後は実ファイルの件数・SHA-256・内容・画像QA結果を照合する。

## Gate 1 — 公開データ
- PublicリポジトリとGitHub Pagesには公開審査済みの素材のみ置く。機微情報を含むログ・画像メタデータ・QA証跡は非公開保管先に分離する。
- 公開前にJSON、HTML、画像、メタデータ、ビルド生成物、配信可能な全ファイルを確認する。未審査の成果をPRやCI artifactにもアップロードしない。
- 非公開保存先が確認できない場合は公開領域を代替利用しない。

## Gate 2 — 実装・継続性
- mainと既存作業ブランチへ直接上書きせず、専用ブランチとPRで差分を管理する。
- 大量処理は小分けし、基準SHA、処理済み件数、成果物の所在、検証結果、再開条件を永続Checkpointに記録してreadbackする。
- 保存失敗時は成果喪失を伴う後続処理を停止する。

## Gate 3 — 品質保証
- 教材の正確性、季節・月の地域差、出題形式、画像の識別精度・著作権・ライセンスを検査する。
- 既存学習履歴キー、スタンプ、進捗保持、旧問題との互換性を回帰検証する。
- iOS 10.3.3 Safariの構文互換・AppCache MIME・初回キャッシュ完了・オフライン再起動(L3)・画像表示・進捗保持を検証する。
- 自動テスト、CI成功、公開HTTP 200、実ブラウザー、旧iOS実機の証拠を区別する。実機未検証なら実機保証を記載しない。
- 重要変更は別パス査読し、具体的な反証条件とテスト結果を残す。

## Gate 4 — リリース
- PRの最新SHAに対する必須チェック app-ci-build の合格、公開データ審査、画像・教材QA、保存データ非劣化、復旧手順を確認する。
- GitHub公式の必須チェックは最新SHAで判定する。過去の成功やCIのみで完成判定しない。
- 重大な未解決Gateがある場合はmainへのマージ・公開を保留する。
- 公開後はコミット・配信ファイル・ブラウザー表示をreadbackする。旧iOS実機の未検証は別途明示する。
